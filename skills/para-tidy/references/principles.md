# Principles

The rules `para-tidy` files by. They are deliberately few; a user's house-rules
file overrides any of them.

## PARA sorts by actionability, not topic

| Category | Holds | Test |
|---|---|---|
| **Projects** | Work with an outcome and an end: a move, a tax filing, a trip, an application | Will this ever be finished? |
| **Areas** | Responsibilities with a standard to keep up, never finished: health, finances, home, work | Is this something I maintain? |
| **Resources** | Topics of interest and reference material: articles, talks, courses, templates, keepsakes | Would I keep this even if nothing depended on it? |
| **Archive** | Anything inactive from the three above | Is it done, retired, or dormant? |

Areas and resources look alike and are not. An area carries an obligation — if
you neglect it, something goes wrong. A resource carries interest — if you
neglect it, nothing happens.

## Where does this go? Three questions

Ask in order and stop at the first yes:

1. Which **project** will this help finish?
2. If none, which **area** does it serve?
3. If none, which **resource** topic does it belong to?

If every answer is no, it is a removal candidate — offer the Trash, per item —
or, if the topic recurs, a new resource.

When an item fits two places, prefer the more actionable: project, then area,
then resource. Research used by a live project lives in the project; extract
the durable parts to a resource when the project closes.

## File by the area a thing serves

A document has more than one property: what it is about, and what kind of
document it is. A folder tree can sort by only one of them. Choose the area it
serves — where you will need it when you act — and get every other view from
search or tags.

So health insurance lives under Health, home insurance with the home, a pension
plan with personal finance or retirement. When you want to see "all insurance",
search for it. Two trees for one set of files restarts the argument every time
something new arrives.

## One home per thing

Every document and every subject has one canonical folder. Two folders for the
same subject (`Insurance/` and `Health Insurance/`, `Taxes/` and `Tax 2024/`)
are a finding, not a style choice. Merge them.

## Keep it shallow

Three levels below the top is usually enough; four needs a reason. A folder with
one child is a level that does no work. Do not create a folder for one file;
create one when a topic is recurring, distinct and likely to accumulate.

## Projects end

A project folder has an outcome and, when it is done, it moves to the archive —
with a line on what came out of it, and reusable material extracted to
resources first. Folders under Projects that will never end are areas or
resources in disguise. Choose one archive convention and keep it: a single
top-level Archive, or a `Done` folder inside each category — not both.

## Keepsakes are resources

Material saved because it was meaningful, motivating or funny — quotes,
comics, talks, letters — is a resource, not part of the area that prompted it.
Give it its own resource folder (e.g. `Inspiration`), so the area stays about
the obligation.

## Labelled exceptions

Some folders must not be forced into PARA: folders managed by an app, shared
folders, encrypted vaults, code repositories, photo and media libraries. Keep
them at the top level, name them in the house rules as exceptions, and leave
their insides alone.

## Naming

- Date-first where order matters: `YYYY-MM-DD_Source_Original-name.ext`. Use the
  date of the event (visit, purchase, statement period) and say so in the house
  rules. Keep the original name or reference number after the prefix.
- Plain, specific folder names. `Misc` is a confession.
- Prefixes (`0-`, `1-`, `_`, `z_`) only for ordering, and used consistently.
- Do not put amounts, account numbers or other sensitive details in file names.

## Upkeep

PARA stays useful only if it is maintained: empty the inbox regularly, move
finished projects to the archive, and record decisions in the house rules so
they are made once.
